# AI-Plantgraphy PWA 仕様書

## 1. 概要

本プロジェクトは、既存の AI-Plantgraphy を別プロジェクトとして再設計し、`PWA` として配布する。

目標は次の 2 点である。

1. ユーザーの導入手順を `インストール + APIキー入力` だけにする。
2. 自宅PCや常時稼働サーバーなしで、Android スマホ単体でも完結して使えるようにする。

本仕様では、バックエンド常駐型ではなく、`静的配信 + 端末内保存 + LLM API 直接呼び出し` を基本方式とする。

---

## 2. ゴール

- PWA としてインストールできる
- Android で快適に使える
- 観察画像、観察履歴、図鑑データをユーザー端末内に保存できる
- Gemini などの LLM API を、ユーザーが設定した API キーで直接利用できる
- 植物観察、図鑑生成、再解析、手動修正、削除、エクスポート/インポートができる
- オフラインでも既存データの閲覧ができる

---

## 3. 非ゴール

- サーバー側DBによるクラウド同期
- 複数端末間の自動同期
- ユーザーアカウント管理
- 運営側でのAPIキー管理
- App Store / Google Play 向けのネイティブアプリ化

---

## 4. 想定ユーザー体験

### 初回導入

1. ユーザーが GitHub Pages などで公開された URL を開く
2. PWA をホーム画面へ追加する
3. 初回起動時に API キーを入力する
4. 以後はそのまま観察・図鑑機能を使える

### 日常利用

1. 写真を 1〜3 枚選んで観察を追加する
2. 端末内で画像を保持する
3. LLM API に画像とプロンプトを送り、解析結果を取得する
4. 観察履歴と図鑑情報を端末内に保存する

### バックアップ

1. 任意のタイミングで ZIP か JSON をエクスポートする
2. 別端末ではインポートで復元する

---

## 5. システム構成

### 5.1 配信方式

- フロントエンド: GitHub Pages などの静的ホスティング
- アプリ形態: PWA
- バックエンド: なし
- AI 利用: ブラウザから LLM API に直接アクセス

### 5.2 推奨技術

- フレームワーク: React + TypeScript
- ビルド: Vite
- PWA: `vite-plugin-pwa` もしくは Workbox
- 端末保存:
  - 構造化データ: `IndexedDB`
  - 画像: `IndexedDB` または `OPFS`
- IndexedDB ラッパー: `idb`

### 5.3 外部依存

- Gemini API
  - 初期対象の LLM
  - 将来的に OpenAI / Anthropic を切り替え可能な設計にしてもよい

---

## 6. データ保存方式

### 6.1 保存方針

全データは原則としてユーザー端末内に保存する。

- API キー: 端末ローカル保存
- 観察データ: IndexedDB
- 図鑑データ: IndexedDB
- 画像データ: IndexedDB または OPFS
- UI 設定: localStorage または IndexedDB

### 6.2 保存先の使い分け

#### IndexedDB

保存対象:

- 観察レコード
- 図鑑レコード
- 解析結果JSON
- 候補、特徴、不確実な点
- 設定情報

#### OPFS または IndexedDB Blob

保存対象:

- 元画像
- サムネイル

推奨:

- 初期実装は `IndexedDB Blob`
- 容量や速度問題が出たら `OPFS` へ拡張

### 6.3 バックアップ

- 全データを `ZIP` でエクスポート
- 全データを `ZIP` でインポート
- 画像 + JSON メタデータをまとめる

## 8. 機能要件

### 8.1 観察追加

- 1〜3 枚の画像を選択できる
- 撮影日、メモ、場所ラベルを設定できる
- 画像は圧縮して保存できる
- 送信前にプレビューできる

### 8.2 植物解析

- 画像を LLM API に直接送る
- 軽量モデルでも動く短く堅牢なプロンプトを使う
- 出力は厳格 JSON を要求する
- スキーマ違反時は 1 回だけ再試行する
- それでもダメなら失敗として扱う

### 8.3 解析進行管理

- `queued` / `analyzing` の進捗表示
- 経過秒表示
- 強制停止ボタン
- 異常終了時は `analysis_failed` に回収

### 8.4 観察詳細

- 画像表示
- 解析結果表示
- 候補表示
- 特徴表示
- 不確実な点表示
- 生JSON表示
- 手動修正
- 再解析
- 強制停止
- 削除

### 8.5 図鑑

- 観察から植物図鑑を自動作成
- 名前から図鑑を手動生成
- 手動生成は `和名のみ入力`
- AI が学名を十分な確度で特定できたときだけ生成
- 既存図鑑がある場合は新規生成せず既存詳細へ案内
- 図鑑再生成
- 図鑑削除
- 図鑑削除後も観察から図鑑再生成可能

### 8.6 検索

- 和名
- 学名
- 特徴文
- 手入れメモ

### 8.7 エクスポート / インポート

- 全データのエクスポート
- 全データのインポート
- バージョン番号を持つ

## 9. 手動図鑑生成仕様

### 9.1 入力

- 和名のみ必須
- 学名入力欄は設けない

### 9.2 処理フロー

1. 和名で既存図鑑を検索
2. 見つかれば生成せず、既存図鑑ありメッセージを表示
3. 見つからなければ AI に和名から学名を推定させる
4. 学名推定の確度が閾値以上なら図鑑本文を生成
5. 閾値未満なら作成せず、別名や正式名の再入力を促す

### 9.3 学名推定ルール

- 入力和名を別の和名へ置換しない
- scientific name が曖昧なら生成しない
- 誤った図鑑を作るより、止めることを優先する

## 10. AI 利用仕様

### 10.1 API キー

- ユーザーが設定画面で入力する
- 平文表示は最小限にする
- 端末ローカルに保存する

### 10.2 セキュリティ前提

この設計では API キーはクライアント端末に置かれるため、バックエンド保護型より安全性は低い。

そのため:

- 個人利用・小規模配布を主対象とする
- 一般大規模公開では運営側バックエンド方式を別途検討する

### 10.3 モデル選択

- デフォルトは軽量・低コストモデル
- 設定で変更可能
- モデル名はユーザーが理解しやすい選択肢に限定する

## 11. PWA 要件

### 11.1 必須要件

- `manifest.webmanifest`
- `service worker`
- ホーム画面追加
- オフラインでの既存ページ表示
- アイコン
- スプラッシュ対応

### 11.2 オフライン要件

オフライン時に可能なこと:

- 既存観察の閲覧
- 既存図鑑の閲覧
- 画像閲覧
- エクスポート

オフライン時に不可なこと:

- 新規AI解析
- 手動図鑑生成

### 11.3 キャッシュ

- シェル部分をキャッシュ
- 画像は必要に応じてローカル参照
- 更新時はバージョン付きアセットで破壊的キャッシュを避ける

---

## 12. UI/UX 要件

### 12.1 最重要方針

- 初回導線は短くする
- 設定は最小限にする
- 画像アップロードから解析まで迷わせない

### 12.2 初回導線

1. アプリ説明
2. API キー入力
3. モデル選択
4. すぐ観察追加

### 12.3 設定画面

- API プロバイダ
- API キー
- 利用モデル
- 保存済み場所ラベル
- データエクスポート
- データインポート
- ローカルデータ削除

---

## 13. エラーハンドリング

### 13.1 代表ケース

- API キー未設定
- API キー不正
- モデル名不正
- 通信失敗
- JSON パース失敗
- 推定不確実
- 画像形式不正
- 保存容量不足

### 13.2 表示方針

- 原因を短く明示する
- 次に何をすればよいかを書く
- 開発者向け生ログは必要時のみ展開表示

---

## 14. 性能要件

- 初回表示: 3 秒以内を目標
- 一覧表示: 100件程度で実用速度
- 画像アップロード時はリサイズ・圧縮を行う
- 大画像でも端末メモリを圧迫しすぎない

---

## 15. データ互換・移行

### 15.1 エクスポートフォーマット

- `manifest.json`
- `observations.json`
- `plants.json`
- `images/`

### 15.2 バージョン

- フォーマットバージョンを持つ
- 将来の破壊的変更時に移行処理を入れる

### 15.3 現行AI-Plantgraphyからの移行

- 既存 SQLite / 画像フォルダを JSON + 画像へ変換する移行スクリプトを別途用意する
- 初期移行は PC 作業でもよい

---

## 16. リスク

### 16.1 大きいリスク

- API キーがクライアント側にある
- ブラウザ保存領域の上限に影響される
- 機種変更時に自動同期されない
- 画像が多いとストレージ消費が大きい

### 16.2 緩和策

- 画像圧縮
- エクスポート/インポート
- 保存容量表示
- 削除導線の明確化
- 低信頼時は止める方針

## 18. 受け入れ条件

- Android で PWA としてインストールできる
- API キー入力後、自宅PCなしで観察追加から解析まで完了できる
- 観察・図鑑・画像が端末再起動後も残る
- 既存図鑑がある植物名では重複生成しない
- 名前から図鑑生成で曖昧な場合は止まる
- エクスポートしたデータを別端末へインポートできる

---

## 19. 補足方針

本仕様は、「一般ユーザー向けに導入手順を最短化する」ことを優先している。

そのため、

- バックエンドなし
- クライアント保存
- API キーをユーザー保持

という割り切りを採用する。

将来的にユーザー数拡大を狙う場合は、別プロジェクトとして `バックエンド保護型` へ再設計する。
